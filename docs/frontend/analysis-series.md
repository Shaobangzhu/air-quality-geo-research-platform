# Analysis time-series contract — milestone 06

Analysis is the sole full time-series route. Map Explorer selects a monitoring identity and links here; `/data` receives source/selection context for later methodology/export work. The light layout contains four compact controls, one chart, a slim station/summary/comparison sidebar and concise observation notes. The supplied design image is styling context only; no example station, value or date was copied as evidence.

## One bounded batch, one chart vocabulary

`GET /api/analysis-series` accepts `region`, canonical `pollutant`, `measurementType`, `mode`, optional historical `snapshotId`, optional hourly UTC `endAt`, `windowHours=24|48|72`, and optional `stationIds=<primary>,<comparison>,<comparison>`. IDs must be unique opaque station IDs; maximum three. Repeated query keys, extra fields, larger windows and arbitrary regions are rejected. Without IDs the first available identity in the bounded batch becomes the deterministic default; explicit Map links always preserve their primary identity. No API request occurs per point, hover or keyboard inspection.

The endpoint shares BFF acquisition, bounded cache, in-flight coalescing and provider guards with station reads. Station IDs do not partition the underlying cache; comparison reads reuse a batch. Mode, pollutant, measurement kind, interval/window and historical snapshot still do. Region presets clip the parent acquisition. All candidate identities come from supplied records for the selected pollutant/extent/window, not a fabricated network census. Candidate metadata is bounded to 256 identities; response selection is at most three series/216 slots, with at most 2,000 original observation revisions in total. There is no response pagination for this bounded endpoint.

The response retains `meta` requested context and original available coverage, acquisition label/origin/credential-free reference, primary ID, missing requested IDs, candidate interpretations and selected series. Each selected series retains full original observation records, slot-to-observation ID references, an explicit comparison reason when blocked, and derived summary fields when comparable. Shared Zod refinement checks timestamps/context, source identity/mode, reference consistency, slot membership, units/interpretations, slot state/count and summary recomputation. Returned numbers are source observation values; no averaging, unit conversion or AQI calculation occurs.

## UTC slots and period interpretation

Windows select observation timestamps in `[from, to)`, with hourly UTC endpoints. A 24/48/72-hour request has exactly 24/48/72 **timestamp slots**, generated by adding 3,600,000 milliseconds in UTC. Slots are bookkeeping positions, not synthetic environmental records. Missing slots have no observation ID or value. They do not assert that a provider promised hourly completeness. No input record is rounded, resampled or moved to another timestamp.

A series is eligible for an hourly line only when every supplied selected-kind record has:

- `period.meaning=hourly`, explicit UTC start/end boundaries exactly one hour apart;
- an observation timestamp on the UTC hour, equal to either its interval start or interval end;
- one consistent unit, alignment, averaging description and source time-zone description across the series.

The alignment is inferred only from equality to explicit source interval boundaries and displayed as `interval-start` or `interval-end`. It is not assumed from an AirNow label, fetch time, fixed GMT offset or the word “hourly.” Periods with unknown boundaries, off-grid timestamps, daily/NowCast meaning, mixed units or mixed interpretations remain available as source records but cannot form this hourly chart. No inferred interval is fabricated. Interval-end observations are positioned at their original end timestamp; the selected window is defined by timestamp, not an integrated exposure or full-interval containment calculation.

For comparisons, the primary and each comparison must have identical normalized unit and verified interpretation. Different unit (including ozone ppm versus ppb), alignment, averaging text or source time-zone description blocks the comparison with a plain reason. Exact textual matching is deliberately conservative; a later reviewed semantic equivalence mapping may relax it. UTC timestamps permit display in Los Angeles without reinterpreting source LST/GMT-offset metadata as civil time. Unknown timezone abbreviations are preserved as metadata, never used to parse ambiguous local dates.

`Intl.DateTimeFormat` displays `America/Los_Angeles` with PST/PDT. Spring-forward skips the nonexistent local hour; fall-back displays distinct UTC instants as 01:00 PDT and 01:00 PST. The inspector includes full UTC strings so repeated local hours remain distinct. It never buckets or deduplicates by local clock labels.

## Missing values, conflicts and counts

| Slot state         | Meaning                                                          | Plotted / numeric count                                  |
| ------------------ | ---------------------------------------------------------------- | -------------------------------------------------------- |
| `observed`         | Exactly one supplied record with a numeric value                 | Original value; zero and negative concentration retained |
| `null`             | Exactly one supplied record explicitly has a null value          | Gap; missing count                                       |
| `absent`           | No supplied record within the source batch's declared window     | Gap; unreported count and missing count                  |
| `outside-coverage` | No record, and timestamp lies outside the declared source window | Gap; outside-coverage count and missing count            |
| `conflict`         | Multiple supplied revisions at the same timestamp                | Gap; separate conflict count; all revisions retained     |

Exact duplicates were already deduplicated by normalization. Conflicting revisions are never selected arbitrarily or averaged. A source batch's declared window is not proof of continuous station coverage. The chart shades requested timestamps outside the available source window; the counts distinguish this from in-window missing records. All slots still retain UTC positions.

Per-series min/max use only single comparable numeric observations. Available count counts these slots, not raw revision count. Missing count = absent + explicit null + outside coverage. Conflict count is separate, so available + missing + conflict = requested slots. Min/max are null when no comparable numbers exist. Peak time is emitted only for a unique observed maximum with no conflicting slots; ties/conflicts omit it. These are observed-window descriptive values, not estimates of unobserved peaks or provider completeness. The sidebar explains this method.

## Sample, historical and live evidence

Sample is explicitly synthetic. The existing standalone fixture is unchanged: declared coverage `[2026-01-14T21:00Z, 2026-01-15T21:00Z)`, actual records concentrated at 17:00–20:00Z on Jan 15. The 72-hour request starts Jan 12 at 21:00Z; the first 48 slots are outside supplied source coverage. PM2.5 Alpha 00A has four numeric concentration values (0, -0.2, 12.4, 15.5), Alpha 00B has three numeric values plus an explicit null, and Beta has three numeric values with an absent 19:00Z record. No data was extended to create a visually continuous chart. Fixture validation status remains unknown.

Historical requires an identified stored snapshot with official historical provenance. Analysis may extend a bounded requested window before that snapshot's coverage, marking outside coverage, while retaining the snapshot's original fetch/acquisition date and source reference. Endpoints beyond snapshot end or windows without overlap remain unsupported. Existing station endpoints retain their stricter full-window historical behavior. Synthetic snapshots cannot impersonate historical mode. The actual PostgreSQL integration replay uses an explicitly synthetic snapshot; official historical and live semantics use labeled test doubles because no official historical acquisition exists locally.

Live still requires a real, officially reviewed AirNow wire codec. It remains contract-unverified and unavailable. A ready key or environment flag does not enable it; no browser AirNow request or hidden sample fallback exists. Unit/provider failure cases verify honest unavailable behavior. Source preliminary/validated/unknown status is displayed independently from mode and chart style.

## Routing and accessible charting

Existing validated `stationId`, pollutant, metric, region, mode and historical snapshot fields carry through from Map. Analysis adds `windowHours=24|48|72` (24 default) and `compare=<id>,<id>` (at most two unique secondary IDs, canonical sorted order, excluding primary). Invalid URL values use safe defaults. Changing primary/pollutant/metric clears comparison context; window changes retain selected identities. A linked primary absent from the active context remains explicitly unavailable and is not replaced silently. The user can select a deliberate replacement from actual candidates.

One analysis request is canceled/ignored on context changes; response mode/region/bbox/pollutant/metric/window/snapshot/selected identities must match before rendering. Chart loading/error/empty states remain explicit. Map discovery requests are suspended while Analysis is active. A new Analysis context requires its own read; unchanged-context hover, click, tooltip and keyboard inspection are local operations. Initial development StrictMode/reloads can start and cancel an extra HTTP read; bounded BFF coalescing still applies.

[Recharts 3.10.1](https://recharts.github.io/en-US/api/Line/) is loaded only with the chart, with matching React-is 19.3.1. It supplies responsive SVG, time axes, line gaps and its [keyboard accessibility layer](https://github.com/recharts/recharts/blob/main/storybook/stories/API/Accessibility.mdx). At this bounded scale it avoids custom path/hit-test maintenance; measured bundle size is reported in the milestone report. `type=linear`, `connectNulls=false` and disabled animation preserve gap boundaries; straight segments join adjacent supplied hours and do not generate interpolated values.

Station lines have distinct solid/dashed/dotted styles, dark colors and text labels; colors do not represent AQI categories. Axis labeling includes the one measurement kind and source unit. Hover/click reveals station, local/UTC time, value/unit, source status, period and acquisition fields. A native timestamp selector and Previous/Next controls provide equivalent inspection without a pointer, with explicit missing/conflict/source-coverage text. Native station/filter selects and comparison checkboxes have labels and disabled explanations. A nonfocused skip link is clipped so offscreen screenshot capture cannot expose it; keyboard focus restores its normal visible presentation. The nonmodal Map drawer behavior remains unchanged.
